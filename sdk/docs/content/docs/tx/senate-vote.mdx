Records an approve/reject vote on an open governance proposal, signed by
the hotkey (not the coldkey — senate membership is tied to the hotkey).
Fails if the hotkey is not currently a senate member or if the proposal
hash and index do not match an open proposal. Votes matter until the
proposal closes; find open proposals and their hashes via the chain's
triumvirate/senate proposal state.

| Signer | Pallet | Wraps |
| --- | --- | --- |
| `hotkey` | SubtensorModule | `SubtensorModule.vote` |

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `hotkey_ss58` | string | no | Senate-member hotkey casting the vote; defaults to the wallet's hotkey. |
| `proposal_hash` | string | no | Hash of the proposal being voted on, as 0x-hex. |
| `index` | integer | no | Index of the proposal in the active proposal list. |
| `approve` | boolean | no | True to vote in favor, false to vote against. |

Address parameters (`--hotkey`, `--coldkey`, `--dest`, ...) accept a raw ss58
address, an address-book or proxy-book name, or a local wallet/hotkey name.

## CLI

Preview with `--dry-run` (shows fee, effects, and policy result without
submitting), then submit:

```bash
subtensor tx senate-vote --dry-run
subtensor tx senate-vote -w my_coldkey
```

## Python

```python
import subtensor as sub
from bittensor_wallet import Wallet

wallet = Wallet(name="my_coldkey", hotkey="my_hotkey")
intent = sub.SenateVote()

async with sub.Client("finney") as client:
    plan = await client.plan(intent, wallet)   # fee, effects, policy — no submission
    result = await client.execute(intent, wallet)
    if not result.success:
        print(result.error.code, result.error.remediation)
```

Or build it by op name, as an agent would:
